왼쪽의 '상황'은 플레이어에게 발생하는 입력이나 조건을 의미
```
예시

이동 입력  
공격 입력  
턴 시작  
행동 종료 등
```
이러한 '상황'은 가운데의 **State Pattern**으로 전달된다.

State Pattern은 현재 어떤 상태(State)를 사용해야 하는지 판단하며, 상황에 따라 상태를 변경하거나 유지한다.

오른쪽의 상태 1, 상태 2, 상태 3은 각각 서로 다른 행동을 담당하는 State다.
```
예시  

상태 1: 이동 상태  
상태 2: 공격 상태  
상태 3: 대기 상태
```
각 상태는 자신의 역할에 맞는 기능만 처리하며, 상황에 따라 뺐다 끼웠다 하듯 다른 상태로 전환될 수 있다.

위쪽의 Player Controller는 직접 모든 행동을 처리하는 것이 아니라, 현재 연결된 State를 통해 행동을 수행한다.

Player Controller는 현재 상태에게 행동을 맡기고, State Pattern은 상황에 따라 상태를 관리하는 구조이다.

상태패턴은 상태별 역할을 분리할 수 있어 코드의 복잡도를 줄이고, 기능 추가 및 유지보수(삑사리 줄임)를 쉽게 할 수 있다는 장점이 있다.

---

요약:

상황이 발생하면 State Pattern이 현재 어떤 상태를 사용할지 결정한다.

Player Controller는 현재 연결된 State에게 행동을 맡긴다.

각 State는 자신의 역할에 맞는 기능만 담당하며, 상황에 따라 다른 상태로 전환된다.
