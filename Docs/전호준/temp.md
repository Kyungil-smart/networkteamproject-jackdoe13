**작성일:** 2026-05-13
**작성자:** 전호준
**사용 환경:** Unity 6000.9f1 / VS Code

## 1. 학습 목표
* 유한 상태 기계(FSM)의 개념을 이해하고, 조건에 따라 오브젝트의 행동 상태가 매끄럽게 전환되는 구조를 설계한다.
* `Update` 함수 내에 복잡하게 얽힌 `if-else` 구조를 탈피하여 코드 가독성과 유지보수성을 높인다.

## 2. 구현 내용 및 핵심 로직
* **상황 및 과제:** 
  * 평소에는 지형에 몸을 숨기고(Hide) 있다가, 타겟이 감지되면 찌르듯이 맹렬하게 돌진(Rush)하는 몬스터 패턴 구현.
  * 숨기, 돌진, 대기(재사용 대기시간)의 세 가지 상태를 명확하게 분리하여 제어.
* **해결 방법 (핵심 접근):** 
  * `enum`을 활용하여 상태를 정의하고, `switch` 문을 통해 상태별 진입, 실행, 종료 로직을 캡슐화.

### 1. MonoBehaviour 클래스와 일반 C# 클래스(상태 패턴)의 차이점

**[MonoBehaviour 상속 클래스] (PlayerController)**

* **소속:** 씬(Scene) 안의 게임 오브젝트에 'component'로 부착되어야만 존재함.
* **실행 주체:** 유니티가 직접 관리함. Awake, Start, Update 등의 함수를 유니티 엔진이 알아서 자동으로 호출.
* **인스펙터 창:** 유니티 에디터의 인스펙터 창에 변수들이 노출되어 직접 눈으로 보고 수정할 수 있습니다.
* **주 역할:** rigidbody 같은 물리 충돌, 렌더링 등 유니티 기능을 연결해서 쓸 때 사용.

**[일반 C# 클래스] (State)**

* **소속:** 게임 오브젝트에 부착X, '메모리 상'에만 존재.
* **실행 주체:** 유니티 엔진이 알아서 실행안함. PlayerController 등을 통해 직접 Update()를 호출해야만 작동함.
* **인스펙터 창:** 대체로 인스펙터 창에 안보임. (로직용)
* **주 역할:** 데이터 계산, 메모리 관리 등에 사용함.

### 2. 두 클래스 간의 생성 방법 차이점

**[MonoBehaviour 상속 클래스 생성 방법]**
* **주의:** 절대 `new` 키워드를 사용하여 생성하면 안 됨. (에러발생)

**[일반 C# 클래스(상태) 생성 방법]**
